# 接入指南：把上下文模块接进你的 AI 开发助手

三种接入方式，按改造量从小到大：

| 方式 | 改造量 | 适合谁 | AI 助手会主动调用吗 |
|---|---|---|---|
| **A. MCP 服务端** | 半天 | 有 MCP 客户端的（Claude Code / Cursor / Qoder / Continue 等） | ✅ 会 |
| **B. 命令行 + 提示词模板** | 10 分钟 | 任何 AI 对话工具 | ❌ 你手动粘 |
| **C. Python API** | 1 小时 | 自己写 Agent 循环 | ✅ 你自己决定 |

---

## 方式 A：MCP 服务端（推荐）

### A.1 什么是 MCP

MCP（Model Context Protocol）是一个让「AI 助手」调用「外部工具」的通用协议。
标准做法是：你的程序在标准输入输出上跑一个 JSON-RPC 服务，客户端（IDE 插件、CLI）
启动它、列出它提供的工具、然后在需要的时候调用。

对这道题的意义：**模块不只是一个库，它是一个可以被任何 MCP 客户端直接使用的能力**。
你不需要为不同的 AI 助手各写一套适配。

### A.2 本模块提供的 5 个工具

| 工具 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `resolve_context` | `task`(必填), `session_id`, `files[]`, `min_score`, `format` | Markdown / JSON | **核心**：给一个开发任务，返回当前有效的规格、契约、决策、代码、验证 |
| `check_verification` | `verification_id`(可选) | 文本列表 | 「先前的验证现在还作不数」 |
| `list_artifacts` | `kind`(可选) | 文本列表 | 列出全部制品及生效状态 |
| `export_handover` | `task`(必填), `notes`, `open_questions[]`, `decisions_made[]` | JSON 快照 | 导出交接快照 |
| `import_handover` | `snapshot`(必填) | JSON 报告 | 导入快照，回查哪些过期了 |

### A.3 配置客户端

**通用写法**（各客户端字段名略有差别）：

```json
{
  "mcpServers": {
    "sdd-context": {
      "command": "python",
      "args": [
        "-m", "sddctx", "mcp",
        "--context", "/abs/path/to/project/context.json",
        "--code-root", "/abs/path/to/project"
      ]
    }
  }
}
```

> **必须用绝对路径。** MCP 客户端启动服务时的工作目录不一定是你的项目目录，
> 相对路径会解析到奇怪的地方。

**Windows 用户注意**：如果 `python` 不在 PATH 里（见新手上手指南 2.1），把 `command` 改成
`py`，`args` 去掉 `"python"` 那一项：

```json
{
  "mcpServers": {
    "sdd-context": {
      "command": "py",
      "args": ["-m", "sddctx", "mcp", "--context", "C:\\proj\\context.json"]
    }
  }
}
```

**Claude Desktop**（Windows）：`%APPDATA%\Claude\claude_desktop_config.json`
**Claude Desktop**（macOS）：`~/Library/Application Support/Claude/claude_desktop_config.json`
**Cursor**：项目根目录 `.cursor/mcp.json` 或全局 `~/.cursor/mcp.json`
**Continue**：`.continue/config.json` 的 `mcpServers` 段
**其他 MCP 客户端**：找它的 `mcpServers` 配置项，填上面的 JSON 即可。

### A.4 验证 MCP 起来了

不用开 IDE 就能测。手动发几行 JSON-RPC：

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | python -m sddctx mcp --context data/fixtures/sample-app
```

期望：

```json
{"jsonrpc": "2.0", "id": 1, "result": {"protocolVersion": "2024-11-05", "capabilities": {"tools": {"listChanged": false}}, "serverInfo": {"name": "sdd-context-manager", "version": "1.0.0"}}}
```

列工具：

```bash
echo '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | python -m sddctx mcp --context data/fixtures/sample-app
```

调用工具：

```bash
echo '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"resolve_context","arguments":{"task":"给订单增加按订单维度的折扣"}}}' \
  | python -m sddctx mcp --context data/fixtures/sample-app
```

返回的 `result.content[0].text` 就是可以直接贴进提示词的 Markdown。

### A.5 在提示词里怎么用

建议在 AI 助手的系统提示或项目规则文件里加一条：

> 开始实现任何改动前，先调用 `resolve_context` 获取当前有效的工程上下文。
> 严格遵守其中的「生效中的需求规格 / 接口契约 / 设计决策」。
> 「已失效」部分里的内容禁止再使用。
> 如果某个验证显示为 `stale_code`，不要假设它验证过的结论还成立。

这样 AI 助手每次动手前都会先问一次「我该遵守什么」。

## 方式 B：命令行 + 提示词模板

不想折腾 MCP？最直接的办法。

### B.1 一个包装脚本

Linux / macOS（`sdd-context.sh`）：

```bash
#!/usr/bin/env bash
# 用法: ./sdd-context.sh "给订单增加按订单维度的折扣" [任务涉及的文件 ...]
set -euo pipefail
TASK="$1"; shift
ARGS=()
for f in "$@"; do ARGS+=(--file "$f"); done
exec python -m sddctx resolve "$TASK" \
  --context "${SDD_CONTEXT:-context.json}" \
  --code-root "${SDD_CODE_ROOT:-.}" \
  "${ARGS[@]}"
```

Windows（`sdd-context.bat`）：

```bat
@echo off
setlocal
set SDD_CONTEXT=context.json
if not "%SDD_CODE_ROOT%"=="" set SDD_CONTEXT=%SDD_CODE_ROOT%
python -m sddctx resolve "%~1" --context %SDD_CONTEXT%
```

### B.2 提示词模板

```
以下是我这次任务的工程上下文（由 SDD 上下文模块生成，只包含当前有效的部分）：

{{把 sdd-context.sh 的输出整段贴在这里}}

请基于以上上下文开始工作。如果你发现某条要求在代码里无法满足，
请明确指出是哪一条、为什么，而不是自己另立一套规则。
```

### B.3 也可以做成 Claude Code / Qoder 的「项目规则」

把下面这段放进项目的 `CLAUDE.md` / `QODER.md`：

```markdown
## 工程上下文规则

本项目的规格、契约、设计决策记录在 `context.json`。
开始任何改动前，先运行：

    python -m sddctx resolve "<任务描述>" --context context.json --code-root .

并把输出当作硬约束：
- 「生效中的需求规格 / 接口契约 / 设计决策」必须遵守
- 「已失效、禁止再照做的制品」里的内容禁止使用
- 验证显示 `stale_code` 时，不要假设原结论还成立
```

## 方式 C：Python API

### C.1 最小例子

```python
from sddctx.store import ContextStore
from sddctx.model import Task
from sddctx.resolver import resolve
from sddctx.render import render_prompt_context

store = ContextStore.load("context.json", code_root="/abs/path/to/repo")

task = Task(
    text="给订单增加按订单维度的折扣计算",
    session_id="session-42",
    files=["app/order.py"],           # 可选：明确知道要改哪些文件
)
bundle = resolve(store, task)

prompt = render_prompt_context(bundle)          # 给模型看的 Markdown
data = bundle.to_dict()                         # 给程序看的 dict
```

### C.2 结构化使用

```python
# 只要规格
specs = [a.id for a in bundle.specs]

# 只要「已失效的决策」——这是题目明确要求的
dead_decisions = [i.artifact.id for i in bundle.invalidated_decisions]

# 只看不再成立的验证
stale = [v for v in bundle.verifications if not v.valid]
for v in stale:
    print(v.artifact.id, v.state, v.detail)

# 冲突（已裁决）
for c in bundle.conflicts:
    print(c.key, "以", c.winner.id, "为准")

# 覆盖缺口：哪些要求完全没有有效验证兜底
for g in bundle.coverage_gaps:
    print(g.artifact.id, g.reason)
```

### C.3 常用参数

```python
resolve(
    store,
    task,
    min_score=0.10,        # 相关性阈值，调低召回更多
    max_code_refs=12,      # 最多返回多少个代码引用
    max_verifications=20,  # 最多返回多少条验证
    kinds=["spec", "decision"],   # 只看某几类制品
)
```

### C.4 在 Agent 循环里用

```python
import json, subprocess, sys

def ask_with_context(store, task_text, llm):
    bundle = resolve(store, Task(text=task_text))
    system = render_prompt_context(bundle)
    return llm(system=system, user=task_text)
```

或者直接用 MCP 客户端 SDK 调本模块（如果你已经在用 MCP 生态）：

```python
# 用 MCP 客户端的通用方式启动本模块并调用
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    params = StdioServerParameters(
        command="python",
        args=["-m", "sddctx", "mcp", "--context", "context.json"],
    )
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            result = await session.call_tool(
                "resolve_context", {"task": "给订单增加按订单维度的折扣计算"}
            )
            print(result.content[0].text)

asyncio.run(main())
```

> `mcp` 这个 Python 包是**可选**的，模块本身不依赖它。
> 如果评测环境没有 pip 网络，用方式 B 或方式 C 的直接 API 调用。

## 三种方式的取舍

| 场景 | 推荐 |
|---|---|
| 日常用 Claude Code / Cursor 写代码 | **A（MCP）**——助手自己会调 |
| 只想快速验证一下效果 | **B（命令行）** |
| 在写论文 / 做实验 / 批量跑评测 | **C（Python API）** |
| 评测机上没有 pip 网络 | **B 或 C**（本模块零依赖） |
| 需要跨会话交接 | A 和 C 都支持（`export_handover` / `import_handover`） |

## 常见接入问题

| 症状 | 原因 | 解决 |
|---|---|---|
| MCP 客户端里看不到工具 | 启动命令的路径不对 | `command`/`args` 全部用绝对路径 |
| 工具调用报「未知的工具」 | 协议版本不匹配 | 本模块用 `2024-11-05`，确认客户端支持 |
| `resolve_context` 返回的内容为空 | `context.json` 没配 `status: active` | 用 `report` 命令检查生效情况 |
| 验证全是 `unknown` | 没建立基线 | `python -m sddctx baseline --context ... --code-root ...` |
| 相关代码推荐不相关 | `scope`/`keywords` 配得太窄 | 补 `scope`、补 `keywords`，或调低 `min_score` |
| 改了代码但验证没变 stale | 该验证没有 `recorded_files` | 跑 `baseline`；确认 `closure` 设置正确 |
