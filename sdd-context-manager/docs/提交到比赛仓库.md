# 提交到大赛团队仓库

> 本模块是第六届 OceanBase 数据库大赛初赛赛题
> **「现有所致，面向软件持续演进的 SDD 上下文管理系统」**的作答代码。
> 这份文档说明它怎么进团队仓库、提测表怎么填。

---

## 1. 仓库与分支约定

| 项 | 值 |
|---|---|
| 团队仓库 | `https://github.com/hechuan1023/OB-2026-PowerContext.git`（提测表里「使用大赛报名登记的团队仓库」，不可改） |
| 本模块在仓库里的位置 | `sdd-context-manager/`（子目录，不影响仓库里其它赛题的代码） |
| 分支 | `feature/sdd-context-manager` |
| Commit | 用 `git rev-parse HEAD` 取 |

**为什么不直接提到 `main`**：提测表按「仓库 + 分支 + commit」定位代码。
单独开分支，评委拉到的就是**这次提交的确切快照**，不会因为仓库随后又有别的提交而对不上。
分支确认没问题后，随时可以 `git merge` 回主分支。

---

## 2. 完整操作步骤

### 第 1 步：克隆团队仓库到本地

```bash
git clone https://github.com/hechuan1023/OB-2026-PowerContext.git PowerContext
cd PowerContext
git checkout main && git pull
```

### 第 2 步：把本模块复制进去

```bash
# 从本模块所在目录的上一级执行；把 <路径> 换成你本机的实际位置
cp -r <路径>/sdd-context-manager ./sdd-context-manager
```

> 复制前先删掉 Python 缓存，避免把垃圾带进仓库：
> `find sdd-context-manager -name "__pycache__" -type d -exec rm -rf {} +`

### 第 3 步：建分支、提交

```bash
git checkout -b feature/sdd-context-manager
git add sdd-context-manager
git status                       # 确认只有 sdd-context-manager 下的文件
git commit -m "feat: SDD 上下文管理器（现有所致，面向软件持续演进的 SDD 上下文管理系统）"
```

### 第 4 步：推送

```bash
git push -u origin feature/sdd-context-manager
```

### 第 5 步：取提测表要填的值

```bash
git rev-parse HEAD        # → Commit id，粘到提测表的「Commit id」
git branch --show-current # → feature/sdd-context-manager，粘到「Branch」
```

### 第 6 步：提交前自检

```bash
# ① 确认没把密钥带进去
git ls-files | grep -E '\.env$|credentials|secret|\.pem$|\.key$' && echo "危险！"

# ② 确认模块在仓库里
git ls-files sdd-context-manager | head

# ③ 确认从仓库根目录能跑起来（评委就是这么跑的）
cd sdd-context-manager
python -m unittest discover -s tests -t .     # 期望：Ran 68 tests … OK
python scripts/demo_change.py                 # 期望：18/18 项通过
```

## 3. 评委怎么验证这道题

模块自带的 `data/self-context/` 是**本模块自己**的上下文，22 条制品、7 条带真实指纹基线的验证，
所以评委 clone 下来不需要任何外部仓库就能看到完整效果：

```bash
cd sdd-context-manager

# ① 模块回答「这个任务该遵守什么、要改哪些文件」
python -m sddctx resolve "给模块新增一种制品类型，需要改哪些文件" \
       --context data/self-context --code-root .

# ② 全部制品的当前效力
python -m sddctx report --context data/self-context --code-root .

# ③ 真的改一次生产代码，看验证是否立刻失效
#    （脚本会自动改回来）
python scripts/demo_change.py
```

第 ③ 步是最关键的一步：脚本会**真的改** `data/fixtures/sample-app/app/pricing.py` 里的
`int(round(discounted))` → `int(discounted)`，让示例工程自己的单测从绿变红，
再让模块如实报告 `stale_code`。这是**实际发生的代码变动**，不是模拟。
