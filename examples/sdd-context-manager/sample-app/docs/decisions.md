# sample-app 设计决策记录

## ADR-001 金额一律用「分」为最小单位（生效中）

- 决定：所有金额在系统内部用整数分表示，只在展示层转成元。
- 理由：浮点金额累加会产生精度误差，退款对账时无法自证。
- 作用范围：`app/**`

## ADR-002 折扣在客户端计算（已被取代，禁止再照做）

- 决定：折扣由客户端计算，服务端只信任客户端传来的折后金额。
- 作用范围：`app/pricing.py`、`app/order.py`
- 被取代原因：客户端可以篡改折后金额，存在资损风险。
- 取代者：ADR-003

## ADR-003 折扣在服务端按订单维度计算一次（生效中）

- 决定：折扣只在服务端按订单维度算一次，不做逐行商品折扣。
- 作用范围：`app/pricing.py`、`app/order.py`
- 生效日期：2026-03-01

## ADR-004 支付重试固定退避 200ms（生效中）

- 决定：重试间隔固定 200ms，不做指数退避。
- 理由：网关故障通常在秒级恢复，指数退避会让用户多等。
- 作用范围：`app/payment.py`

> ADR-002 和 ADR-003 的差别看起来只是「折扣算在哪」，但它直接决定信任边界，
> 所以 ADR-002 必须被显式标记为失效，否则 AI 助手会照着旧决策实现出有资损风险的代码。
